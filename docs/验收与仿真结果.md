# 软件验收与仿真结果

整理日期：2026-10-02。软件 V1.0.0。实物测试尚未开始，本章所有数值结果均来自电脑端实际运行的仿真。

## 可复核的完成项

桌面 C 共享库和 STM32 ARM 固件均编译通过。Python 3.14 本机验收 57 项测试通过，包括状态机、时钟回绕、CRC、序号去重、日志改动检测、串口应答丢失、重启核对、本地 HTTP 接口和实际运行归档。串口测试使用可控的设备替身，并非连接真实 STM32。

第一次冻结版本的 54 项验收记录：`evidence/20261002_113308_922208_verification/`。页面测试后追加日志边界修复，57 项复核记录：`evidence/20261002_115158_244253_verification/`。源码与二进制 SHA-256、命令、返回码、Git 版本在 `result.json`；原始输出在 01/02/03.log。后续发布核验保存在同一 evidence 目录的新时间子目录中。

十种场景均已在本机完成运行：正常、卡料、错出口、入口漏检、重复进料、出口粘连、断联、急停、重启、重复指令。详细数据保留在 2026-10-01 的运行目录；控制故障矩阵也包含在当前 57 项测试中。

## 冻结版本的独立对照

Git：`ae0ecc22225a7a477232f92dab35e3895ac6b200`，运行时工作区干净。种子 20000–20019；每组 24 件；四种策略，合计 80 次、1920 次物料任务仿真。

原始汇总：`data/benchmarks/20261002_113318_030624/`。每次事件轨迹通过 cases.csv 中的 run_id 关联到 data/runs/。

| 策略 | 平均加权迟交 / s | 平均工期 / s | 平均准时率 | 平均换向次数 |
|---|---:|---:|---:|---:|
| FIFO | 239.956 | 31.942 | 34.58% | 11.85 |
| EDD | 229.304 | 32.040 | 31.04% | 12.00 |
| GREEDY | 93.239 | 25.637 | 51.67% | 2.15 |
| BEAM | 73.122 | 26.742 | 49.58% | 3.85 |

BEAM 相对 GREEDY 的加权迟交减少约 21.6%，配对平均差 -20.117 s，95% bootstrap 区间 [-26.119, -13.886]。相应代价是平均工期增加 1.105 s、换向增加 1.70 次。准时率平均差 -2.08 个百分点，区间跨零，不能确认准时率存在稳定差异。

因此当前证据支持在这组任务分布下用多步搜索降低加权迟交；当更重视工期和换向次数时，GREEDY 是值得选择的简单基线。不能将上述结论写成对任何生产任务都更优。

## 已有记录的保留

第一次三策略 60 次实验、第二次四策略 80 次实验和本次独立种子 80 次实验分别保存，不覆盖、不混算。第一轮和第二轮种子同为 12000–12019，用于阶段开发与方法检查；正式独立复核换用 20000–20019。

前序验收中的失败输出同样保留，包含 SQLite 文件占用、Python 3.14 的 HTTP 拒绝连接问题，以及在 DLL 使用期间重建导致的构建失败。修复及复核记录见 CHANGELOG.md 和开发阶段.md。

页面测试还发现了数字键回读排序造成的事件摘要误报。修复前的两份页面记录 `20261001_205424_032482_3e899c`、`20261002_113952_241505_a76e36` 原样保存，会显示事件校验失败，不能把它们写成已通过的证据。已追加数字键、键冲突及拒绝事件后序号连续性三项测试；命令行正式对照记录的数据结构不触发此问题。修复后的页面记录重新生成、校验和导出。

Git 记录采用实际操作日期，当前身份按先前确认的本仓库配置使用。文件摘要可以核对内容是否改变，不是作者身份、过去开发时间或获奖水平的证明。
