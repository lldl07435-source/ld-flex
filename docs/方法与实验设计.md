# 方法、假设与评价

## 1. 可恢复执行

每个任务采用 `(session, command_id, route)` 标识。命令 CRC 正确、会话匹配、编号有效、入口和出口清空、设备空闲，才会接受执行。相同编号且路线相同返回已有任务确认；同号不同路线拒绝；更小编号拒绝。任务逻辑编号与串口应答序号分开。

控制器上电状态 LOCKED。操作员确认通道清空并按住本地按钮后才允许 ARM。任务结束需要先看到入口、再看到指定出口、最后等所有光电清空稳定。门打开次数和确认完成数分别统计；二者不一致时不能通过修改统计口径消除差异。

上位机下发 RUN 后若丢失应答，不自动换编号重发。任务记为 unknown，要求核对。重新上电丢失 MCU RAM 中的去重记忆，因此本工程不保证掉电期间物理动作的严格 exactly-once；它提供的是“检测到不确定性后停止派发并人工对账”。CRC 用于串口误码检测，不构成网络认证。

## 2. 同一控制核心

`core/cell.c` 和 `core/wire.c` 分别编译成桌面共享库与 STM32 固件。Python 通过 ctypes 调用共享库；不存在另一套 Python 控制逻辑替代它。仿真环境生成传感器事件，C 核心据此产生相同状态机决策。

可迁移部分是逻辑与时序判定；没有模拟的部分包括光电电气噪声、舵机负载、惯性、板卡电源压降、机械卡滞方式、串口中断时延。因此共享源码能减少控制逻辑分叉，不能证明模拟机构与实物动力学一致。

## 3. 排产问题

任务 j 含到达时刻 r、交期 d、优先权重 w、目标路线 k、预计加工时长 p。一次只能处理一个任务；执行中的任务不抢占。切换路线附加准备时间 s，默认 0.65 s。这个参数表示换型/人工准备代价，不是已经测得的舵机旋转时长。

评价量：

```
T_j = max(0, C_j - d_j)
加权迟交 = Σ w_j T_j
准时率 = 及时完成件数 / 确认完成件数
窗口代价 = Σ [w_j T_j + 0.15(C_j - 当前时刻)] + 0.8 × 换向次数
```

0.15 与 0.8 是固定工程权重，未由测试集搜索得出，也不宣称普适最优。unknown 在安全实验单独计数；排产性能比较采用正常无故障场景，避免丢掉失败任务后得到虚假的低迟交。

| 策略 | 决策方式 | 用途 |
|---|---|---|
| FIFO | 最早到达优先，编号打破平局 | 常见简单派发 |
| EDD | 最早交期优先 | 交期基线 |
| GREEDY | 同一窗口代价和剩余任务下界，只搜索下一件 | 搜索深度消融 |
| BEAM | 最早交期候选最多 8 件、深度 4、宽度 24 | 多步权衡 |

BEAM 每次只执行所选序列的第一件，下次重新计划。排序包含尚未排入序列的任务代价下界：假设剩余任务可在当前节点之后立即独立加工，不增加切换，计算最早可能的迟交和流动时间。这个乐观下界防止搜索一味逃避难处理的高权重任务。候选截断和束宽截断使方法不保证全局最优。

只使用已经到达的任务。未来随机故障和实际通行扰动不参与调度选择；仿真预先按 seed 与物料编号绑定扰动，四种策略看到相同物料扰动，不能因为执行次序不同重新抽取有利样本。

## 4. 统计协议

早期基准种子 12000–12019；最终冻结算法后使用独立种子 20000–20019。每种子 24 件；每种策略运行一次，形成 20 对配对差。按种子整体 bootstrap 2000 次，报告均值和百分位 95% 区间；不把同一运行里 24 件物料当成 24 个独立重复。

所有 4 个指标、3 个基线比较均公开，是探索性分析，未做多重检验修正。区间跨零时不写“稳定提升”。固定种子便于复算，不代表数据来自真实工厂；后续实测需使用独立任务集。

第一轮三策略结果保存在原始阶段记录。加入 GREEDY 后发现并处理窗口之外高权重任务的估计问题，形成第二轮版本；两轮不能混成一份同版本结果。源码摘要、Git dirty 标记和参数随每次运行保留。

## 5. 进一步达到竞赛深度的实验

先完成电气和机构稳定性，再测真实通行时间与换向准备时间的分布。将模型参数冻结后，另选未参与校准的订单测迁移误差；报告仿真预测工期与实测工期偏差。

然后检验是否值得使用深度 4：与 GREEDY 的收益、每次决策耗时、最长等待时间共同比较。可把深度 2/4/6、候选 4/8/12 作为独立消融阶段，但参数表必须在测试前冻结，不能反复看测试集选最好的一组。

最后做恢复处置对照：安全停机后“整批清空重做”与“仅隔离未知物料、继续已确认队列”在同一故障时刻的恢复时间和返工数。这项实物对照尚未执行，不能提前填数。现场发生风险时优先停止，不为录制效果故意卡住舵机烧毁电源。
