# 竞赛推进表

目标是按全国性工程竞赛的完整度准备：问题、方法、系统、对照、实物和答辩相互对应。比赛名额和奖项取决于当届赛题、评审与实测表现，本文件不预设结果。

## 六周执行

| 周次 | 你负责的动作 | 软件侧工作 | 过关证据 |
|---|---|---|---|
| 1 | 跑完电脑端、能解释一次故障；汇总采购价格 | 已提供仿真、协议、日志和对照 | 自己运行的一次正常和一次卡料记录 |
| 2 | 装台架，核对引脚、电平、光电极性 | 根据实际器件调整配置 | 接线照片、输入位测试、Git |
| 3 | 标定舵机和通行时间，完成 180 件基础分流 | 根据真实分布修正模型 | 全部通过/失败记录和视频 |
| 4 | 完成至少五类故障各十次 | 检查日志、修正误报与漏报 | 故障矩阵与恢复表 |
| 5 | 按固定任务集跑策略对照 | 统计配对差、生成图表、解释失败条件 | 原始 CSV、脚本、报告 |
| 6 | 录制完整演示、整理成本和硬件照片、模拟答辩 | 整理开源版本和作品说明 | 可复现工程、视频、展示材料 |

周次是安排，不是过去已经发生的开发记录。每周实际完成后再由 checkpoint 工具保存提交。

## 演示脚本（约五分钟）

1. 展示台架和预算，说清小批量任务切换、卡料后的物料对账问题。
2. 正常分流两件，展示传感器确认及时间戳。
3. 制造一次可控的入口漏检或断联：控制器锁定，页面出现 unknown，旧任务不会自动再放料。
4. 核对物料、清空、按物理确认按钮恢复；展示故障前后的原始事件。
5. 展示四策略相同订单的对照图及不确定性；展示 Git 版本、源码与复现实验入口。

## 五个答辩问题

- 为什么手工上料也值得研究？答：降低验证机构成本，隔离“派发与恢复”的问题；同时承认吞吐量受操作者影响，需要记录和控制该因素。
- 为什么不声称掉电后恰好执行一次？答：物理动作与记账不是原子事务，掉电时必须通过传感器或人工核对恢复可信状态。
- 为什么同一 C 核心有意义？答：减少仿真和固件的控制逻辑分叉，但传感器、电源和机构仍要实测。
- 算法是不是原创？答：FIFO、EDD、束搜索属于已有方法；本工程研究的是具体约束下的整合与验证，创新点是否成立须通过相关工作对比和实测支持。
- 如果 GREEDY 与 BEAM 没有显著区别怎么办？答：保留结果，优先考虑更简单的策略，并分析哪些负载和准备代价下多步搜索才有价值。

## 报名检查

先找学院负责竞赛的老师确认学校认可的赛事清单、年级资格、队伍人数和当届指定平台。嵌入式芯片与系统设计竞赛应用赛道是候选，不是已经确认的报名资格。下一届正式通知发布后再决定是否更换指定开发板；当前台架可以继续完成算法和控制实验。
