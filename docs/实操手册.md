# LD-Flex 实操手册

适用版本：1.0.0。电脑系统：Windows；本机交付解释器：Python 3.14。先完成第一部分，暂时不用买硬件。

## 1. 五分钟跑通电脑端

1. 用 PyCharm 打开 `C:\Users\30434\PycharmProjects\0922`，项目解释器选本目录 `.venv\Scripts\python.exe`。
2. 运行 `app.py`，或在资源管理器双击 `启动项目.cmd`。控制台显示 `http://127.0.0.1:8876`；浏览器应自动打开。
3. 保留正常场景、24 件、种子 42，点击“开始仿真”。约十几秒后看到 24 件确认完成。
4. 把场景改成“卡料”，再运行。第 3 次放料进入故障；点“确认已清空”继续。结束后应有 23 件完成、1 件未知。
5. 打开“运行记录与重放”，选择刚才的记录。查看事件、校验摘要、导出 ZIP。

一件未知表示当时没有足够信号确认它的去向。在实物里，你要找到这件物料后再处理；系统不会静默重发它。

### 看哪些文件

| 文件 | 用途 |
|---|---|
| `data/运行日志.log` | 服务启动、页面请求、错误信息；按大小轮转 |
| `data/runs.sqlite3` | 历史列表索引 |
| `data/runs/运行编号/meta.json` | 实际开始时间、模式、参数、Git 版本、源码摘要 |
| 同目录 `events.jsonl` | 每次命令、控制状态变化和任务结果，实际时间与虚拟时间分开 |
| 同目录 `jobs.csv` | 仿真每件物料的开始、结束、交期、结果 |
| 同目录 `summary.json`、`manifest.json` | 汇总与文件摘要 |

不要把整份项目解压到系统保护目录。日志只说明记录中的时间和过程；并不能单独证明某个人在过去完成过某项开发。

## 2. 跑对照实验

页面“调度对照实验”默认 20 组、每组 24 件，四种策略共 80 次仿真。操作完成后，页面显示均值与配对差异，`data/benchmarks/日期时间/` 保存 HTML、JSON 和 CSV 报告。每次运行的完整日志仍在 `data/runs/`。

重新打开工作台时，对照页面会载入最近一次完整报告。完整的正式 20 组结果位置见本手册最后的验收与结果章节；后续小规模操作测试会形成自己的独立目录。

命令行也可运行。执行前关闭正在运行的工作台，避免两个进程同时管理同一数据目录：

```powershell
.\.venv\Scripts\python.exe tools\experiment.py --benchmark --seeds 20 --count 24
.\.venv\Scripts\python.exe tools\experiment.py --matrix --count 12
```

第二条跑十种场景。命令行故障批次会在虚拟等待 2 秒后执行“模拟操作者清空”；页面演示则等待你点击确认。两种恢复来源都记录在日志里。

报告里的加权迟交越小越好，准时率越大越好。不要只挑一张好看的曲线；比较同一批任务，连同不利结果一起保留。

## 3. 验收与阶段 Git

先关闭工作台和批量实验，再双击 `一键验收.cmd`。本机已配置桌面 GCC 和 ARM GCC，会依次构建共享控制库、运行自动测试、构建 STM32 固件。结果位于 `evidence/日期时间_verification/`。任何一步失败，最终状态就为失败。

在 PyCharm Terminal 中，日常改动完成后执行：

```powershell
.\.venv\Scripts\python.exe tools\checkpoint.py "完成入口光电极性核对并补充实测记录"
git log --oneline --decorate -8
git status --short
```

引号内换成这次真正完成的内容。此工具会跑软件测试、创建本地 Git 提交、保存当前时间记录。没有源码变化时不会硬造空提交。固件或引脚改变还须额外运行 `tools/build.py --arm`。

实际照片、视频、票据、未脱敏原始日志放 `evidence/`，默认不进入 Git。准备公开的记录应先整理到 `docs/experiments/`，明确来源为实测或仿真，再提交。别把只改日期的文件当作旧的开发历史。

## 4. 采购与加工（约两个周末）

预算表在 `hardware/bom.csv`。这是分项预算上限，不是已经下单的报价。含基础工具 382 元、运费 38 元、预留 80 元，合计 500 元；电脑已有。购买前汇总最终含运费价格，超过 500 元就优先借万用表和焊接工具、自制底座，不买摄像头或机械臂。

先购买控制板、下载器、USB-TTL、三只光电模块、两只工作舵机和一只备用、电源。光电模块必须核实供电和输出规格；优先 3.3V 供电、低电平有效的对射或槽型模块。反射式模块对材质敏感，需单独测试，不能照搬阈值。

机械尺寸见 `hardware/结构尺寸.svg`：建议底座约 320×240 mm，主滑槽长 180 mm、净宽约 28 mm，侧壁高 25 mm，末端分为两路。试验物料先使用同批轻质方块，约 15–20 mm、单件不超过 10 g。滑槽从约 20° 坡度开始调整，以物料能稳定通过且不会飞出为准。

第一个舵机控制闸门，第二个控制分流板。闸门前只放一件物料，出口不能直接落到桌外。滑槽内壁尽量光滑。批量储料、自动分离多个相邻物料不属于当前机构能力，先把人工单件上料做稳定。

## 5. 接线与第一次上电（约 1–2 小时）

完整表见 `hardware/wiring.md`。必须先不接舵机电源完成下面检查：

1. 量控制板 3.3V、舵机 5V；确认共地。USB-TTL 采用 3.3V 逻辑，TX 接 PA10、RX 接 PA9。
2. 入口/左/右光电接 PA0/PA1/PA2；模块输出若为 5V，先做可靠电平转换。不能把“供电 5V”直接等同于“信号可接 3.3V 输入”。
3. PB0 经常闭急停触点接地。正常为低，按下或断线为高。PB1 经独立常开确认按钮接地。急停不是确认按钮。
4. ST-Link 接 3.3V 参考、GND、PA13、PA14。用 STM32CubeProgrammer 通过 SWD 烧写 `build/ld-flex.bin`，地址 `0x08000000`，烧写后校验。
5. 再接舵机，先拆掉机械连杆空载观察。确认关闭位置、开闸位置、左右位置不会顶到机械限位，再装回连杆。

固件默认使用内部 HSI 8 MHz。具体板卡、晶振标称和第三方板兼容性没有实物验证；烧录后从“实物连接”检查串口握手。输出 PWM 50 Hz，默认闸门 1000/1600 μs，左右 1100/1900 μs。实际舵机行程需按你的机构修改 `firmware/main.c` 顶部四个常量并重新构建、烧录。

## 6. 实物单件测试（约 30 分钟）

打开“实物连接”，刷新串口、连接。连接后控制器仍应是 LOCKED。先挡住一个光电，设备反馈的 `inputs` 应分别为入口 1、左 2、右 4；全空为 0。逐个核对，记录照片和日志。

清空通道、释放急停，按住 PB1 确认按钮，勾选页面的现场确认，点击“建立 / 复位设备会话”。设备变为 IDLE 后松开按钮。

把一件物料放在闸门前，填写编号 `sample-001`，选择 A 路，点击执行。应依次经过 ALIGN → RELEASE → TRANSIT → SETTLE → DONE。换 B 路重复。若故障，先断开舵机电源或停止，找到未确认物料，排查原因，再清空、确认和复位。

每次最多一个物料。实物页面当前提供人工单件派发；仿真批量排产是已经实现的软件实验。要进行实物策略对照，使用预先记录的相同任务清单，按对应派发顺序人工上料，并记录真实时间；不要把自动供料仿真当成实物全自动产线。

## 7. 必须完成的实测

| 顺序 | 操作 | 通过条件 | 留存 |
|---|---|---|---|
| A 电气与信号 | 逐个遮挡光电、按急停、断开急停线 | 输入位与预期一致；急停不能启动 | 接线照片、串口日志 |
| B 基本分流 | 左右各 30 件、重复 3 轮 | 每件核对实际出口；不合格原因逐条记 | 180 件任务表、视频 |
| C 故障注入 | 卡料、错出口、入口漏检、断联、重启各 10 次 | 正确锁定；不自动重复放料；未知物料不计正常产量 | 故障表、日志、视频 |
| D 时序标定 | 量上料、换向、通过、恢复耗时 | 替换仿真默认参数；保留测量分布 | 校准表、参数提交 |
| E 排产对照 | 相同订单四策略，随机化策略测试顺序 | 保留全部运行、失败和比较结果 | 同任务配对数据和报告 |

这些是计划数量，不是已经完成的实测。没有示波器时可以用手机慢动作测动作延迟，报告视频帧率和一帧带来的不确定度；不能把电脑 10 ms 仿真步长写成实物响应精度。

## 8. 常见问题

| 表现 | 处理 |
|---|---|
| 浏览器打不开 | 看 PyCharm 控制台是否仍在运行；手动打开打印的地址；确认旧窗口未占端口 |
| 数据目录已被使用 | 关闭本项目旧窗口或正在跑的命令行实验；不要删除锁文件强行绕过 |
| 控制库未构建 | 运行 `python tools/build.py`；新电脑先安装 GCC 并设置 `CC` |
| DLL Permission denied | 工作台或实验还在用控制库；关闭它们后重跑验收 |
| 无串口 | 核对 USB-TTL 驱动、线材、设备管理器；执行 `pip install -r requirements-hardware.txt` |
| 复位被拒绝 | 按住 PB1；释放 PB0 急停；三个传感器均清空；活动任务先停止 |
| 一直 TIMEOUT | 看入口/出口信号、供电、光电位置和舵机行程；先单件，不提高速度掩盖问题 |
| 记录 interrupted | 上次进程异常退出；查看最后事件，保留未知状态，不补写成功 |

新电脑安装：Python 3.11+、GCC、可选 ARM GNU Toolchain。`CC` 可指定桌面 gcc 完整路径；`ARM_GCC` 可指定 arm-none-eabi-gcc 完整路径。Linux 使用 `python3 tools/build.py`、`python3 app.py`。自动 CI 会验证桌面控制库和软件测试，板上性能仍需实测。
