# 架构与里程碑

## 数据流

```
任务表 → 排产器 → 操作者上料提示 / 仿真供料
                      ↓
                会话号 + 任务号 + 路线 + CRC
                      ↓
         C 状态机（电脑共享库 / STM32）
             ↓                        ↑
       闸门、分流舵机            入口、左出口、右出口、急停
                      ↓
         状态快照 / 事件 → SQLite + JSONL + CSV
                      ↓
             校验摘要、实验报告、历史重放
```

Python 不承担实物急停判定；STM32 本地处理。CRC 检错不提供身份认证；物理串口用于本地实验。电脑服务只监听回环地址。

## 状态设计

上电 LOCKED → 人工清空并复位 IDLE → 对准 ALIGN → 开闸 RELEASE → 等待通过 TRANSIT → 等待传感器清空 SETTLE → DONE。

任何活动阶段发生急停、超时、走错出口或主机失联进入 FAULT。闸门关闭。复位要求急停解除、三个传感器均为空，且操作者已经核对现场物料。DONE 表示通过传感器确认；FAULT 不能计入正常产量。

MCU 每次启动不信任旧串口字节，必须建立新会话。上位机见到重启、超时或无法确认完成时把当前任务记为未知，禁止自动换新任务号重发。MCU 的去重记忆仅在本次启动内存在；掉电后不宣称物理动作严格只执行一次。

| 阶段 | 优先级 | 完成条件 | 记录 |
|---|---|---|---|
| 1 选题与接口 | P0 | 预算、边界、状态和实验指标明确 | 文档提交 |

## 下一阶段实物门槛

买到硬件后按手册依次完成电气确认、空载标定、单件通行、故障保护、排产对照。软件验收不代替这五项。每一步只提交真实完成的改动和记录；日期使用电脑当前时间，实验运行时间与虚拟时间分别保存。
